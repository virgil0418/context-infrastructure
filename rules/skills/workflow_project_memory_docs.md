# 项目记忆文档维护工作流

## 适用场景

当用户启动一个新项目、新需求、新功能开发、长期调研或跨多轮 session 的工作时，使用这个 skill。

典型触发：

- “开始准备开发”
- “这个需求我们先记录一下”
- “维护 lesson/work 文档”
- “后面每个项目都要记录”
- “接着上次那个项目做”
- 任意需要后续 agent 接手的项目/需求

## 核心原则

每个项目或需求都应该有两份本地记忆文档：

1. `work.md`：当前工作台账，帮助 agent 快速接手。
2. `lesson.md`：经验沉淀，只记录以后能复用的判断。

这两份文档不是交付物装饰，而是项目状态的入口。新的 agent 进入项目时，先读 `work.md` 和 `lesson.md`，再读 README、需求文档、设计文档和代码。

## 文件放置规则

| 场景 | 位置 |
|---|---|
| 独立代码仓库 | 仓库根目录：`work.md`、`lesson.md` |
| 大仓中的子项目 | 子项目根目录：`<subproject>/work.md`、`<subproject>/lesson.md` |
| 单个需求但没有独立仓库 | 需求目录根部：`work.md`、`lesson.md` |
| 一次性调研 | 调研 session 目录根部：`work.md`、`lesson.md` |

优先跟随用户明确指定的文件名。用户没有指定时，默认使用小写：`work.md` 和 `lesson.md`。

## 参考样式

如果用户提供参考文件，先读取参考文件，再抽取格式和维护习惯。当前 workspace 的推荐样式来自：

- `/Users/howie/Downloads/WORKING.md`：当前状态放在顶部，按日期追加工作记录，记录范围、决策、验证命令和下一步。
- `/Users/howie/Downloads/lessons.md`：用编号条目记录可复用经验，每条包含场景、做法和以后如何判断。

迁移到新项目时不需要照抄文件名大小写。独立项目默认使用 `work.md` 和 `lesson.md`，但内容组织应保持“当前状态在前、流水账进 work、经验进 lesson”。

## 创建时机

### 新项目或新需求启动

先创建两份文档，再进入具体开发或调研。

`work.md` 至少包含：

```markdown
# <Project / Requirement Name> — Work Document

## 当前状态

- **最后更新**：YYYY-MM-DD
- **分支**：`<branch>`
- **项目路径**：`<absolute path>`
- **当前阶段**：<一句话说明>
- **主要范围**：<本轮负责什么>

## 需求与设计依据

- `<path>`：<说明>

## 默认工作流约定

<本项目特别的执行规则、构建规则、测试规则、文档同步规则>

## 范围

- [ ] <用例/功能/任务>

## 当前发现的问题

### <问题标题>

<事实、影响、建议处理方式>

## 进行中

### YYYY-MM-DD — <主题>

- [x] <已完成>
- [ ] <下一步>

## 待确认问题

1. <问题、影响、推荐选项>

## 已完成

- [x] <已完成事项>
```

`lesson.md` 至少包含：

```markdown
# Lessons — <Project / Requirement Name>

## 0. <经验标题>

<可复用经验。写原因、触发条件、以后怎么做。>
```

## 更新规则

### 每次开始工作前

1. 读 `work.md` 获取当前状态、范围和待确认问题。
2. 读 `lesson.md` 获取项目特有经验。
3. 如果用户提到“接着做”“继续上次”“准备开发”，先更新 `work.md` 的当前状态和进行中记录。

### 每次发生状态变化时

更新 `work.md`：

- 分支变化
- 范围变化
- 新增或关闭待确认问题
- 完成一个阶段
- 验证命令通过或失败
- 发现设计、需求、代码不一致
- 遇到阻塞项

### 每次形成可复用经验时

更新 `lesson.md`：

- 以后能避免返工的流程经验
- 项目特有约束
- 容易踩坑的接口、构建、测试、架构规则
- 需求文档与实现之间的冲突处理方式
- 已验证有效的调试或开发路径

不要把普通流水账写进 `lesson.md`。流水账放 `work.md`。

## 写作标准

### `work.md`

- 写事实，不写情绪。
- 保留绝对路径和分支名，方便接手。
- 待确认问题写清影响和推荐选项。
- 进行中任务用 checkbox，避免重复执行。
- 过期状态及时移动到“已完成”或删除。

### `lesson.md`

- 每条经验回答三个问题：什么时候触发、为什么重要、以后怎么做。
- 不记录“我做了什么”，记录“以后遇到同类情况应该怎样判断”。
- 标题要具体，例如“创建类用例必须先确认幂等条件”，不要写“注意事项”。
- 同一经验不要重复写，补充到原条目即可。

## 与其他流程的关系

| 工作类型 | 配合方式 |
|---|---|
| DDD / 后端开发 | `work.md` 记录当前用例、设计文档、测试命令；`lesson.md` 记录领域规则和框架约束 |
| 前端开发 | `work.md` 记录页面范围、交互状态、验收截图；`lesson.md` 记录组件约束和真实 bug |
| 调研任务 | `work.md` 记录问题、资料来源、结论状态；`lesson.md` 记录可复用判断框架 |
| 长期项目 | 每个里程碑都更新 `work.md`，每次踩坑后提炼 `lesson.md` |

## 完成检查

交付前检查：

- [ ] `work.md` 的最后更新时间、分支和当前阶段准确。
- [ ] 新增任务、阻塞项、待确认问题已记录。
- [ ] 形成的可复用经验已沉淀到 `lesson.md`。
- [ ] `lesson.md` 没有写成执行流水账。
- [ ] 新 agent 只读这两份文档，也能知道下一步该做什么。
